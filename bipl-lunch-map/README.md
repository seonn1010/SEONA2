# 비플 점심지도

L.L.M Academy(광주 서구 상무중앙로 44) 반경 600m 안에서 **비플식권·제로페이로 결제할 수 있는 가게**를 지도와 목록으로 보여주는 한 페이지짜리 웹사이트.

- 공개 주소: https://seonn1010.github.io/SEONA2/bipl-lunch-map/ (GitHub Pages, `main` 브랜치)

## 기능
- **지도**(카카오맵 Web SDK): 아카데미 위치, 반경 600m 점선 원, 가게 위치(카테고리별 색). PC는 휠 확대 끔(버튼으로 확대), 휴대폰·태블릿은 두 손가락 확대 가능
- **카테고리**: 전체 / 음식점 / 카페 / 편의점·마트 (휴대폰에서도 한 줄)
- **결제 수단 필터**: 전체 / 비플식권 / 제로페이. 카드에 결제 수단 배지 표시
- **가게 카드**: 음식 종류, 직선거리, 예상 도보 시간(분속 67m), 대표메뉴 2~3개와 가격, 네이버지도·카카오맵 가게 페이지 바로가기
- **검색**: 메뉴·가게 이름, 메뉴 태그(국물·면 등), 음식 종류(한식·중식·일식·양식·분식·아시안·패스트푸드 / 카페·베이커리·디저트). 메뉴 칩을 누르면 같은 메뉴를 파는 곳만 보기
- **별점·후기 요약**: 승인된 후기가 있는 가게는 목록 카드에 별점 평균(참여 인원)과 "후기가 n건 있어요"가 바로 보임
- **12,000원 점심 뽑기** (조합 종류 없이 완전 랜덤)
  - 뽑는 방식: 가격 있는 식사(`kind=meal`) 메뉴 하나를 랜덤으로 고른 뒤, 남은 금액 안에 드는 메뉴를 더 붙일지 말지를 랜덤(50%)으로 정한다. 붙일 땐 종류(식사·음료·디저트)·가게(같은 가게·다른 가게)를 가리지 않고 후보 전체에서 랜덤. 최대 3개
  - 조건: 합계 12,000원 이하, 등장하는 가게끼리 모두 직선 200m 이내, 같은 메뉴 중복 금지, 합계 8,000원 미만이면 버리고 다시 뽑기, 직전 결과와 같은 조합은 피함. 결제 수단 필터를 따름. 가격 없는 메뉴는 제외
  - 결과는 **팝업**으로 뜬다(뒤 화면은 어둡게, 스크롤 잠금): 합계·남는 금액, 가게별 메뉴·가격, 가게 순서대로 도보 동선, 작은 지도(번호 핀 + 점선, 같은 가게 메뉴는 핀 하나)
  - 버튼: [다시 뽑기](팝업 안에서 결과만 바뀜) [지도에서 크게 보기](팝업을 닫고 메인 지도에 같은 동선) [닫기]. X·바깥 영역·ESC로도 닫힘
  - 메뉴가 예전 문자열 형식("메뉴(9,000원)")이면 가게 업종으로 판단(음식점=식사, 카페=음료)
- **가게 상세 + 후기**: 가게 카드를 누르면 상세 영역이 열리고(휴대폰은 아래에서 올라오는 시트, PC는 왼쪽 패널) 지도도 그 가게로 이동
  - 별점 요약(승인된 별점 평균, 소수점 한 자리, 참여 인원), 승인된 후기 목록(최신순, 별점·댓글 따로 표시)
  - 작성: 별 n번째를 누르면 n.0점(다시 누르면 취소), 댓글 300자, 닉네임(비우면 "익명"). 별점만·댓글만·둘 다 가능
  - 등록하면 "관리자 승인 후 보여요". **관리자가 승인한 후기만 공개**

## 파일
| 파일 | 내용 |
|---|---|
| `index.html` | 화면과 동작 전부 (카카오맵 키, Supabase URL·공개 키 포함) |
| `data.js` | 가게 데이터 (`window.META`, `window.STORES`). `tools/build_data_port.mjs`로 생성 |
| `supabase/reviews.sql` | 후기 테이블·제약·RLS 정책. Supabase SQL Editor에서 한 번 실행 |
| `tools/` | 데이터를 만든 스크립트와 중간 결과 |
| `HANDOFF.md` | 다음 작업자를 위한 인수인계 메모 (결정 사항, 남은 일) |

빌드 과정은 없다. 로컬에서 보려면 `tools/serve.ps1`로 http://localhost:8000 을 띄운다(카카오 지도는 등록된 도메인에서만 뜬다).

## 가게 데이터
- **고정 id**: 모든 가게에 `id`가 있다. 후기가 이 id(`store_id`)에 붙기 때문에 **한 번 정한 id는 바꾸지 않는다**.
  - 처음 정할 때 규칙: `kakaoId`가 있으면 `kakao-번호`, 없으면 `naver-번호`, 둘 다 없으면 이름으로 만든 `name-slug`
  - 정해진 id는 `tools/store_ids.json`(가게 이름 → id)에 저장되고, 다시 생성할 때 그대로 재사용된다. 목록 정렬 순서 번호는 id로 쓰지 않는다.
- **결제 수단**(`pay`): `"비플식권"`, `"제로페이"` 중 하나 이상
  - 비플식권: 비플페이 앱의 '전체 가맹점 사용처'·'비플식권 사용처' 화면을 옮겨 적은 목록(2026-11-17)
  - 제로페이: 제로페이 공식 가맹점 찾기(https://www.zeropay.or.kr/UI_HP_009_03.act)에서 수집. 수집일·출처는 `data.js`의 `META.sources`
  - 상호와 도로명주소가 둘 다 맞으면 같은 가게로 보고 하나로 합쳐 배지를 둘 다 붙인다
- **좌표·거리**: 아카데미 좌표(35.1508811, 126.8489117)에서 직선거리, 600m 이내만
- **제외**: 술집·유흥주점·저녁 장사 위주인 곳, 점심에 안 여는 곳
- **메뉴**: 가게마다 네이버 지도(일부 카카오맵) 매장 메뉴 페이지를 직접 열어 확인(2026-11-19). 형식은 `{name, price, kind(meal|drink|dessert), tags, rep}`. 카드엔 `rep` 2~3개만, 나머지는 "메뉴 더보기". 확인 전인 가게는 "대표메뉴 미확인"
- **고치는 곳**: `data.js`는 생성 결과물이라 직접 고치지 않는다. 메뉴는 `tools/menus.json`, 제외 규칙은 `tools/build_data.py`, 제로페이는 `tools/zeropay_merge.json`. 고친 뒤 `tools/build_data_port.mjs`(또는 `build_data.py`)로 다시 생성 (자세한 방법은 HANDOFF.md)

## 후기 저장소 (Supabase)
- 테이블 `reviews`: `id`(uuid), `store_id`, `nickname`, `rating`(1~5, 없어도 됨), `comment`(300자, 없어도 됨), `approved`(기본 false), `created_at`. 별점·댓글 중 하나는 꼭 있어야 한다.
- **RLS(행 단위 보안)** 켜짐
  - 방문자(anon) 읽기: `approved = true`인 행만 서버에서 내려온다. 승인 전 후기는 공개 키로 직접 조회해도 안 보인다.
  - 방문자 쓰기: `store_id`·`nickname`·`rating`·`comment`만 넣을 수 있고 `approved = false`인 행만 허용
  - 방문자 수정·삭제: 권한 없음
- 페이지에는 **공개용 anon(publishable) 키만** 들어 있다. `service_role`/secret 키는 코드에 넣지 않는다.
- **승인 방법**: Supabase 대시보드 → Table Editor → `reviews` → 해당 행의 `approved`를 `true`로 바꾼다. 관리자 페이지는 따로 없다.

## 한계
- 거리는 직선거리라 실제 도보 거리보다 짧다
- 결제 가능 여부와 메뉴·가격은 바뀔 수 있다
- 후기는 같은 사람이 여러 번 올리는 것을 막지 않는다(승인 전엔 공개되지 않음)
